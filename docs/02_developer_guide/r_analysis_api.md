# Extended collection list for R analysis and BRIT-EU package

`GET /waste_collection/api/collection/?view=extended` opts into a paginated export-oriented representation. Without `view`, the existing lean list response and its filtering remain unchanged. Unknown `view` values return HTTP 400. Extended schema `1.0` returns `count`, `next`, `previous`, `results`, `schema_version`, `generated_at` (UTC), and `snapshot_isolation: false`.

Extended rows use `CollectionFlatSerializer` fields plus stable `id` and `publication_status`. Dynamic numeric metrics keep explicit adjacent unit fields: `<property>_<year>` and `<property>_<year>_unit`. Repeated measurements in the same unit keep the last value. When visible measurements for the same property and year exist in several units, every unit is kept under a unit-suffixed key instead (`total_waste_collected_2024_mg_a`, `total_waste_collected_2024_kg_a`, each with its `_unit` field; colliding suffixes get a numeric counter). Existing collection filters apply, and property values as well as regional attribute values (population, population density) are filtered by the requesting user's visibility. Each page loads its dynamic columns with a fixed number of batched queries regardless of page size. `scope=all` is available only in the extended view and requires authentication; other non-public scopes also require authentication. Ordering is by primary key; pages default to 100 and are capped at 200. Extended responses are marked private/no-store. This is a live read, not a database snapshot.

The API is consumed by the BRIT-EU R analysis package, which is not tracked in this repository. The package is hosted in the BRIT S3 bucket under the public media prefix as versioned ZIPs: the complete release `{MEDIA_URL}rscripts/BRIT-EU-R-<version>.zip` including the archived historical input data, and the code-only variant `{MEDIA_URL}rscripts/BRIT-EU-R-Code-<version>.zip` for inspecting the scripts — e.g. <https://flexibi-dst.s3.amazonaws.com/media/rscripts/BRIT-EU-R-1.0.4.zip> for production. Only the `static/` and `media/` prefixes are publicly readable, so new package releases must be uploaded below `media/rscripts/` and the download links on the `/r-analysis/` page bumped to the new version. The separate, single-file live client `BRIT_Datenanalyse.R` is tracked as a BRIT static source file and downloaded with an attachment response from `/r-analysis/BRIT_Datenanalyse.R`. The public `/r-analysis/` page links both downloads and explains how to run them. The complete ZIP ships the fixed historical inputs listed in `data/manifest.json`; they are the archived case-study inputs, never inferred from current database state.

Access to the extended view is restricted to authenticated users who are administrators or hold the `waste_collection.access_analysis_api` capability (`CollectionViewSet.analysis_api_permission`); anonymous requests get 401, other users 403. `sync_roles` provisions the capability to the `analysis_api` group created by `ensure_initial_data`; add users to it in the Django admin. Within the group, object visibility follows the ordinary publication and ownership rules. Deployment requires the ordinary BRIT application release including its migrations and a `sync_roles --apply` run to provision the capability; no new secret is required. The analysis client does not upload data or publish records. A data release can be hosted separately as an immutable directory containing `data/manifest.json` and its checksum-protected `data/raw/` files.

Validation: `sources.waste_collection.tests.test_analysis_api` covers the unchanged default response, opt-in extended contract, pagination, ID filtering, publication scope, owner isolation, zero-valued metrics, units and private metric exclusion. The R client tests ship with the hosted analysis package.
